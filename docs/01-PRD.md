# 01 — PRD (Product Requirements Document)

| Document 01 — PRD | |
|---|---|
| **App Name** | AnExcel |
| **Tagline** | Turn a stack of scanned answer sheets into a ready-to-submit mark list. |
| **Problem** | After evaluating a stack of answer scripts, a professor has to manually total and re-type every student's mark into a spreadsheet, by hand, for every class and every exam. At 70–80+ students per batch this is slow, repetitive, and an easy place to make a transcription error on an official record. |
| **Target User** | An Anna University professor who has just finished evaluating a batch of answer scripts (a single class, or several classes at once) and needs a clean digital mark list, without re-typing marks by hand. |
| **Core Features (Must Have)** | Bulk PDF or image upload (up to ~100 sheets per batch)<br>Automatic alignment of each scan to the fixed Anna University template, then extraction of register number, per-question marks, and totals<br>Arithmetic cross-validation — recomputed totals checked against what the examiner wrote, any mismatch flagged<br>Review queue — only flagged/failed sheets need the professor's attention, everything else auto-approves<br>Manual-entry fallback — any sheet that can't be read gets typed in directly, so one bad photo never blocks a batch<br>Auto-grouping into classes by the first 8 digits of register number<br>Excel export — one row per student: register number, subject code, subject name, total marks, status<br>Per-batch configurable image retention (fixed options only — 1 week to 6 months — no "keep forever")<br>Batch history, permanently browsable, Excel exports never auto-deleted |
| **Nice to Have** | SEMS submission adapter (v2, pending access)<br>Real Anna University login (v2, pending access)<br>Dedicated lightweight digit/tick recognizers, if v1 cost/accuracy data justifies replacing the general vision-model approach<br>Progress notification via browser push when a large batch finishes processing |
| **Out of Scope** | Arrear/backlog student handling (register number outside the batch's prefix)<br>Admin/HOD roles or any permission tier beyond single-professor batch ownership<br>Onboarding/first-use walkthrough<br>Deep DPDP/data-protection compliance work (tool is private, professor-only, limited scope)<br>Correction-feedback capture for retraining extraction models |
| **User Stories** | As a professor, I want to upload a bulk batch of scanned answer sheets, so that I don't have to enter marks one by one.<br>As a professor, I want only uncertain extractions flagged for my review, so that I'm not re-checking every single sheet.<br>As a professor, I want to manually enter a sheet that fails to process, so that one bad photo doesn't block finishing my batch.<br>As a professor, I want the exported Excel to contain only the final total per student, so that it's ready to use as-is.<br>As a professor, I want to choose how long scanned images are kept, so that I control storage without losing evidence I might need for a dispute.<br>As a professor, I want to see a live progress indicator while a large batch processes, so that I know it's working and how much is left. |
| **Success Metrics** | An 80-student batch processes end-to-end with no more than a small fraction of sheets needing manual review or entry<br>A professor can go from "just uploaded" to "downloaded Excel" without needing outside help or documentation<br>Zero cases of an exported Excel row silently containing an unreconciled/incorrect total |
