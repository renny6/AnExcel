# 03 — App Flow (Navigation & User Journey Map)

| Document 03 — App Flow | |
|---|---|
| **Pages List** | `/login` — sign in<br>`/batches` — batch dashboard/history (home after login)<br>`/batches/new` — start a new batch (name, subject/course, retention period)<br>`/batches/[id]/upload` — upload PDF or bulk images<br>`/batches/[id]/processing` — live progress bar while the pipeline runs<br>`/batches/[id]/review` — review queue: flagged sheets, corrections, manual-entry fallback<br>`/batches/[id]/summary` — final confirmation, approve & lock, export/download<br>`/batches/[id]` — read-only batch detail (for already-approved/historical batches) |
| **Navigation Type** | Left sidebar (Batches / New Batch / Settings), standard top bar showing logged-in professor. On mobile: bottom tab bar with the same core destinations. |
| **First Screen** | `/login` for a signed-out visitor. `/batches` for anyone already signed in. |
| **Auth Flow** | Login → `/batches` directly. No signup and no onboarding — professors use pre-provisioned test accounts for v1; real accounts will come from Anna University credentials in v2. |
| **Core User Journey 1 — Process a batch** | Professor logs in → lands on `/batches` → clicks "New Batch" → names it, declares subject/course, picks a retention period → uploads a PDF or a bulk set of images → sees a live progress bar on `/batches/[id]/processing` → lands on `/batches/[id]/review` showing only flagged sheets → corrects fields inline or switches a stuck sheet to manual entry → clicks "Approve & Finalize" on `/batches/[id]/summary` → downloads the Excel file. |
| **Core User Journey 2 — Revisit a past batch** | Professor logs in → `/batches` shows batch history → opens an older batch → downloads its Excel export again (always available) → if within the retention window, can extend that batch's image retention period from the same screen. |
| **Empty States** | `/batches` with no batches yet: a clear prompt to start the first batch, no clutter. `/batches/[id]/review` with nothing flagged: a clear "all sheets auto-approved, ready to finalize" state rather than an empty-looking screen. |
| **Error States** | A sheet that fails alignment: routed straight into the review queue as "couldn't be read," offering the manual-entry option, not a dead end. Upload interrupted mid-batch (network drop): only the failed files need retrying, not the whole batch. Vision API outage: a visible banner on the processing screen ("processing paused, retrying automatically") rather than a silent stall. |
| **Redirects** | After login → `/batches`. After logout → `/login`. After "Approve & Finalize" → `/batches/[id]/summary` with the download ready. After session timeout → `/login`, returning to the same page post re-login where practical. |
