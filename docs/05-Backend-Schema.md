# 05 — Backend Schema (Data Model & Auth Architecture)

| Document 05 — Backend Schema | |
|---|---|
| **Table: professors** | `id` (uuid, PK) · `identity_source` (text — "test" or, later, the real auth provider) · `external_id` (text — the ID handed back by the auth provider) · `name` (text) · `college_code` (text) · `department` (text) · `created_at` (timestamp) |
| **Table: batches** | `id` (uuid, PK) · `professor_id` (uuid, FK → professors.id) · `declared_subject_code` (text) · `declared_subject_name` (text) · `declared_course_batch` (text) · `retention_period` (enum: `1_week`/`2_weeks`/`1_month`/`3_months`/`6_months`) · `images_purge_at` (timestamp, nullable until approved) · `status` (enum: `draft`/`processing`/`ready_for_review`/`approved`/`exported`) · `created_at`, `approved_at` (timestamps) |
| **Table: answer_sheets** | `id` (uuid, PK) · `batch_id` (uuid, FK → batches.id) · `image_storage_key` (text, unique — the idempotency key) · `register_number` (text, nullable until extracted) · `total_marks` (numeric, nullable) · `status` (enum: `processing`/`needs_review`/`auto_approved`/`manual`/`failed`/`reviewed`) · `created_at`, `updated_at` (timestamps) |
| **Table: question_marks** | `id` (uuid, PK) · `answer_sheet_id` (uuid, FK → answer_sheets.id) · `question_no` (text) · `sub_part` (text, nullable) · `marks` (numeric) · `tick_state` (boolean) · `confidence_score` (numeric) · `source` (enum: `auto`/`corrected`) — internal only, never exported |
| **Table: audit_log_entries** | `id` (uuid, PK) · `answer_sheet_id` (uuid, FK → answer_sheets.id) · `professor_id` (uuid, FK → professors.id) · `field_changed` (text) · `old_value` (text) · `new_value` (text) · `created_at` (timestamp) — append-only, no update/delete permission granted at the application layer |
| **Relationships** | `batches.professor_id → professors.id` (many-to-one) · `answer_sheets.batch_id → batches.id` (many-to-one) · `question_marks.answer_sheet_id → answer_sheets.id` (many-to-one) · `audit_log_entries.answer_sheet_id → answer_sheets.id` (many-to-one) |
| **Indexes** | `answer_sheets.batch_id` (fast lookup of a batch's sheets) · `answer_sheets.register_number` (duplicate detection within a batch) · `answer_sheets.image_storage_key` (unique index — enforces job idempotency) · `batches.professor_id` (dashboard/history queries) |
| **Auth Model** | Every request is scoped to the authenticated professor's own data. The only access rule in the system: `batch.professor_id == current_professor.id` — checked on every read/write touching a batch or anything nested under it. No row-level policy beyond this ownership check is needed. |
| **User Roles** | Single role: `professor`. No admin, no HOD, no elevated tier of any kind. |
| **Sensitive Fields** | `register_number` and `total_marks` are treated as sensitive personal/academic data — encrypted at rest via standard managed Postgres encryption (no custom encryption layer needed at this scope). |
| **File/Media Storage Structure** | `/{batch_id}/{answer_sheet_id}/original.{ext}` for source scans (subject to retention purge) · `/{batch_id}/exports/{batch_id}.xlsx` for the final export (never purged) |
| **Webhooks / Event Triggers** | Upload completion → enqueues a per-sheet processing job on the Redis/Celery queue. `Batch.status = approved` → triggers the Excel generation job. Daily scheduled job → purges any `answer_sheets` images past `images_purge_at`. |
| **API Endpoint List (core)** | `POST /api/auth/login` · `POST /api/batches` (create) · `GET /api/batches` (list/history) · `POST /api/batches/:id/upload` (presigned upload + register sheet) · `GET /api/batches/:id/status` (progress) · `GET /api/batches/:id/review` (flagged sheets) · `PATCH /api/answer-sheets/:id` (correction or manual entry) · `POST /api/batches/:id/approve` · `GET /api/batches/:id/export` (download) · `PATCH /api/batches/:id/retention` (extend only) |
