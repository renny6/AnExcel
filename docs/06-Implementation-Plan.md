# 06 — Implementation Plan (Step-by-Step Build Sequence)

| Document 06 — Implementation Plan | |
|---|---|
| **Phase 1: Setup** | Initialize git repo (`git init`, `.gitignore`, initial commit) before any application code. Set up Docker Compose with services for Postgres, Redis, MinIO (local S3-compatible storage), the Next.js frontend, the Next.js API layer, and the FastAPI processing service. Establish the folder structure from `02-TRD.md`. Create `.env.example` listing every required variable name (no values). |
| **Phase 2: Database Schema & Migrations** | Implement the five tables from `05-Backend-Schema.md` (`professors`, `batches`, `answer_sheets`, `question_marks`, `audit_log_entries`) with the specified columns, foreign keys, and indexes. Confirm `answer_sheets.image_storage_key` has a unique constraint — this is what makes per-sheet jobs idempotent. |
| **Phase 3: Authentication Flow** | Build the test-account login provider behind the single pluggable auth interface described in `02-TRD.md` and `05-Backend-Schema.md`. Implement session handling: idle timeout, max session lifetime, secure httpOnly cookies, and basic brute-force protection on login attempts. Seed several distinct test accounts across different colleges/departments. |
| **Phase 4: Core Feature 1 — Upload & Ingestion** | Batch creation form (`/batches/new`) with subject/course declaration and retention-period selection. Upload flow supporting PDF (multi-page) and bulk image upload, with client-side quality pre-check, HEIC→JPEG conversion, and direct presigned upload to storage. Each accepted file registers an `answer_sheets` row and enqueues a processing job. |
| **Phase 5: Core Feature 2 — Processing Pipeline** | FastAPI + Celery worker: deskew and align each image to the fixed template (OpenCV), crop known field regions, then call the Google Gemini API (Flash, free tier) once per sheet with all of that sheet's crops bundled into a single request — not one call per field — to stay well within the free tier's RPM/RPD limits. Run the arithmetic cross-validation described in `05-Backend-Schema.md`/architecture docs. Sets each sheet's status (`auto_approved`/`needs_review`/`failed`). Implements retry-with-backoff and treats rate-limit responses as retryable, not fatal. Worker concurrency tuned to stay under the free tier's actual RPM (verify in Google AI Studio). |
| **Phase 6: Core Feature 3 — Review, Manual Fallback & Export** | Review queue UI (`/batches/[id]/review`) showing only flagged sheets, image + editable fields side by side, plus a manual-entry mode for failed/stuck sheets. Duplicate-register-number detection. "Approve & Finalize" flow that locks the batch and triggers Excel generation (openpyxl) with the schema from `01-PRD.md`/`05-Backend-Schema.md`. Download endpoint. |
| **Phase 7: UI Polish & Responsive Design** | Live progress bar and completion notification (in-app toast + browser Notification API) per `03-App-Flow.md`. Batch history view. Retention-extension control. Apply the full visual system from `04-UI-UX-Design-Brief.md` — confirm no purple or green appears anywhere in the final UI. Responsive pass, especially the mobile upload/camera flow. |
| **Phase 8: Testing** | Build the golden-sample regression set starting with the one verified sample sheet on hand. Unit tests for cross-validation math, duplicate detection, and status transitions. One end-to-end test covering upload → process → review → export. Manually test error paths: alignment failure, upload interruption, vision API failure. |
| **Phase 9: Deploy** | Production-equivalent Docker Compose (or equivalent container deploy) with real managed Postgres and real S3-compatible storage swapped in for MinIO. Configure production environment variables. Confirm the containerized app runs identically to local dev before considering this phase done. |
| **Done Criteria** | A professor can log in with a test account, create a batch, upload a mix of clean and deliberately-bad sample images, watch it process with a live progress bar, review only the flagged sheets (including using manual entry on at least one), approve the batch, and download a correct Excel file — entirely inside Docker Compose, with a clean git history and no purple/green anywhere in the UI. |
